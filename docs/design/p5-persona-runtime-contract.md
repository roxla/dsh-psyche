# P5-0 人格运行时契约

- 状态：P5-0 冻结稿（2026-11-14）
- 依据：DEV v28.06 / 提交 `eb981d2` / Schema v24
- 范围：人格内容来源、初始化校验、运行时投影、宿主共存、失败语义；不含代码与 Schema 迁移
- 关联：`p5-projection-composition.md`、`p5-growth-reflection-contract.md`、`p5-mood-behavior-contract.md`

## 1. 单一权威来源

1. `identity.md` 是唯一的人格内容来源，UTF-8 原文；运行时不摘要、不截断、不重写。
2. `persona.json` 只负责初始化状态、`personaId`、锁定记录与身份哈希；它不是第二份人格文本。
3. SQLite 中的人格字段只是派生快照，不能反向作为运行时来源。
4. `identityHash = sha256(identity.md 的原始字节)`。运行时逐轮校验；哈希不一致时不注入人格。

## 2. 初始化准入

只有同时满足以下条件，`persona-init` 才允许进入 `locked`：

- 文件存在、UTF-8 可解码、无 NUL；
- 字符数 ≤ `persona.maxChars`（推荐 6,000）；
- 估算 token 数 ≤ `persona.maxTokens`（推荐 3,000）；
- 不包含明显的私钥/令牌/凭据模式（按固定规则扫描；命中则拒绝锁定并告警）；
- 哈希写入 `persona.json`。

超限时拒绝锁定，由 Owner 自行删减原文；不允许运行时截断，也不允许模型临时生成摘要充当人格。

已有锁定文件在升级后超限：进入明确的兼容异常状态（`identity-over-budget`），面板告警，不注入；由 Owner 重新编辑并重新锁定，不能静默改写原文件。

## 3. 两层人格，但只有一个投影入口

- **初始人格核心**：`identity.md`。只能由 Owner 的重新锁定流程改变；成长、模型、反思均不可写。
- **成长人格层**：已确认的 Artifact、Habit、Stance、Growth。它不合并进 `identity.md`，也不在人格 Context 中重写；由独立的成长投影在后续对话中体现。
- 禁止把成长层拼成人格原文的一部分，形成“实际人格 = 原文 + 未审计片段”的隐式第二来源。

## 4. 运行时投影

- Context 名称：`psyche-persona`。
- 输入：通过校验的 `identity.md` 原文；无其他内容。
- 时机：每轮 `agent/pre-step` 读取一次快照，组装进当轮 Context；不累积进历史消息。
- 生效：人格变更在下一轮 Context 组装时生效；已发起 Turn 使用原快照。
- 开关：`persona.enabled` 为总开关；关闭时整块不注入，其余投影不受影响。
- 只读：投影过程不写库、不改人格状态、不产生候选。

## 5. 失败语义（失败关闭）

| 情况 | 行为 |
|---|---|
| 未初始化 / `initializing` | 不注入，面板提示 |
| `locked` 且哈希一致 | 注入原文 |
| `identity-drift` | 不注入；不自动接受漂移；等待 Owner 重新锁定 |
| `damaged` | 不注入；不自动恢复默认 |
| 读取异常 / 解码失败 | 不注入，告警；不缓存旧文本顶替 |
| 超出总投影预算 | 不注入人格，保留隐私纪律，告警（见 `p5-projection-composition.md`） |

人格块本身永不截断；宁可不注入，也不注入半段。

## 6. 与宿主 `soul-md` 的共存

- 目标：Psyche 专用 Profile 中，角色身份由 `identity.md` 承担；`soul-md` 只保留宿主通用规则，不再定义另一套聊天性格。
- 不依赖 Prompt 排列顺序解决冲突；顺序不能保证指令优先级。
- 验收必须给出可复制的 Profile 配方（启用/禁用哪些 section）并在真实 Host 上验证。
- 无法消除冲突时：P5-1 模块与投影层可 PASS，但真实 Host 人格一致性记 `PARTIAL`。
- Persona Context 只对绑定 Psyche 的 Agent 生效，不污染其他 Agent。

## 7. 变更与审计

- 修改 `identity.md` 必须走 Owner 的重新锁定流程；普通编辑造成的哈希漂移不得悄悄生效。
- 每次注入记录：`personaId`、`identityHash`、字符数、估算 token、注入结果（成功/失败原因）。
- 不记录人格正文到普通运行日志。
- 回滚：保留旧 `identity.md` 版本与哈希；回滚同样走重新锁定。

## 8. 验收（P5-1）

A 层（确定性，模块）：

- 哈希一致才注入；drift/damaged 不注入；
- 超字符/超 token/含凭据模式拒绝锁定；
- 注入内容与文件原文逐字一致；
- 总预算超限时人格整块省略且隐私纪律保留；
- 开关关闭、卸载重载后无残留、无重复注册。

B 层（确定性，隔离 Host + 探针 Adapter）：

- 探针捕获的最终 system/messages 中出现人格原文；
- 同一轮不重复、不累积；
- 多轮之间只出现一次。

C 层（行为，真实 Provider）：

- 固定模型与版本、temperature 0、同一组问题，比较不同人格预设的可观察差异；
- 只证明“行为有差异”，不宣称最终输入与 A/B 层完全一致。

## 10. v1.1 补充：状态机与计数口径（2026-11-14 冻结）

运行时投影状态（不要求新增 Schema 状态）：

| 状态 | 运行时行为 | Owner 可见信息 |
|---|---|---|
| `ready` | 完整注入人格 | 当前哈希与生效状态 |
| `over_budget` | 不注入人格，聊天继续 | 超限类型与修复建议 |
| `identity_drift` | 不加载未授权人格 | 哈希漂移、重新确认入口 |
| `damaged` | 不注入人格，聊天继续 | 文件或初始化状态异常 |
| `unavailable` | 不注入人格，聊天继续 | 读取失败与稳定错误码 |

补充边界：

1. **异常不得残留旧人格**：上一轮注入成功、当轮哈希漂移或读取失败时，当轮必须不再注入任何旧文本，也不注入修改后的内容。
2. **修复复用既有 Owner 确认与人格初始化治理**，不新增可直接覆盖人格锁定状态的管理 API。
3. 错误日志只记录状态码、哈希校验结果、字符/token 数；不记录完整人格文本。

计数口径：

- 精确计数：已知模型与 tokenizer 时，按实际序列化文本计数。
- 估算计数：无法取得 tokenizer 时，使用版本化保守算法（CJK 1 字≈1 token，×1.2），标记 `estimated`。
- 15% headroom 是包装、格式与计数误差预留，不构成对所有模型的 token 上界。
- 只有已验证的 tokenizer 才可宣称严格 token 上限；否则只声明字符硬上限与估算预算。
- 初始化准入只限制 `identity.md` 本身；运行时准入还必须计入其他 Psyche Context 已占用的预算（P5-1 仅观测，P5-2 才做硬限制）。
