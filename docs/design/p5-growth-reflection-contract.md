# P5-0 成长与反思契约

- 状态：P5-0 冻结稿（2026-11-14）
- 定位：明确“成长是什么、怎么投影、怎么从经历产生、什么不能改”
- 关联：`p5-persona-runtime-contract.md`、`p5-projection-composition.md`

## 1. 定义

- 成长不是第四套存储，而是记忆、心情、人格随经历发生的长期变化。
- 阶段：`trust → autonomy → initiative → integration`（现有 Growth Gate）。
- 成长阶段是**认知进度的描述**，不是权限等级，也不代表事实可信度。
- 成长层可以修正人格的表现与认知倾向，但**不能根本改变人格**（见 §2）。

## 2. 可修正与不可改变

### 允许（须经确认）

- 新习惯、新偏好、新的成熟观点；
- 对既有认知的修订（Revision / Stance）；
- 表达倾向、关心方式、互动节奏的长期变化；
- 对某个 Contact 的关系态度调整。

### 禁止（任何模型输出、反思候选、成长阶段都不得改变）

- `identity.md` 的核心身份、价值观、底线与禁用行为；
- 人格名称、基本来历、核心关系定义；
- 把“成长”当成扩权：不得据此获得新的工具权限、隐私访问、主动联系许可；
- 用累计成长覆盖、重写或绕过原文人格。

需要改变核心人格时，只能走 Owner 的重新锁定流程，并留下显式版本；这不是成长，是重新定义。

## 3. 成长投影（P5-2）

- Context 名称：`psyche-growth`。
- 内容只允许：
  1. 当前阶段的中性描述（例：“关系阶段：自主”）；
  2. 最近一次已确认的长期变化（一句话，带时间）；
  3. 固定边界句：“阶段不是权限，不得据此宣称获得新能力”。
- 禁止注入：`bottleneck`、闸门数值、未确认候选、私域证据、可被模型当成待办的任务句。
- 长度：不超过 3 行 / 300 字符；超预算时整块丢弃（见投影组合契约）。
- 只读：投影不触发 `syncGrowth()`、不写库、不产生候选。

## 4. 确认与展示分开授权

成长被确认，不等于可以向所有 Contact / Room 展示。

- 全局成长：经明确确认、且已抽象为不含私域细节的产物，才可跨 Contact 投影。
- Contact 专属成长：只在对应 Contact 范围内投影。
- Room 专属经验：不得自动进入其他群或私聊。
- 私密证据：不因被抽象为成长就获得公开权限。
- 任何投影前都要通过当前目标 Scope 的 Disclosure 校验；`confirmed` 不能跳过 Scope 检查。

从局部经历形成全局习惯，必须产生独立、可审计的抽象产物，并验证其不包含不允许跨域披露的信息。

## 5. 反思闭环

### 5.1 生命周期

```text
eligible → evaluating → proposed | no_change | failed
```

- `no_change` 是正常结果，不为了凑成长而强行产生候选。
- `failed` 不影响原始对话、Capture 或既有认知。
- 候选在 P5-3a 只生成、不生效；P5-3b 才允许确认与生效。

### 5.2 触发

- 时机：Turn 正常结束或日记生成后；
- 条件：自上次反思以来存在新的、非助手来源的 Source；
- 预算：每 Contact / 每天候选上限、全局上限、单次超时；超限记 `skipped_budget`，不排队补跑。

### 5.3 持久幂等

- **Trigger Key**：`sha256(personaId + 自上次反思以来的新 sourceId 集合)`。同一批 Source 不重复执行。
- **Candidate Semantic Key**：`sha256(subjectRefs + predicate + scope + candidateType)`。同一语义不重复生成相同提案。
- 两个键必须持久化（P5-3 决定落点），能跨重启；内存去重不算完成。
- 语义键不得阻止新证据并入原候选；真正的立场变化按新候选处理。

### 5.4 证据独立性

候选必须引用具体 `sourceIds`，且满足：

- 助手/模型输出不得作为证明自身结论的证据；
- 同一用户消息的重复 Capture 只算一份；
- 群聊转发、引用、同一网页的多个镜像不自动算多份独立证据；
- 来源实体、原始事件与传播关系都要参与独立性判断；
- 证据不足时保留候选或 `no_change`，不得降级为“默认相信”。

### 5.5 候选类型

`new_fact`、`revise_stance`、`new_habit`、`identity_growth`。

- `identity_growth` 与核心人格相关的变更必须 Owner 确认；
- 低影响类型是否允许规则确认，留到 P5-3b 单独拍板，初始默认仍需 Owner 确认。

### 5.6 失败原子性

- 候选生成、校验、确认任一环节失败，不得留下半个已生效认知；
- 反思使用的 Source 与 Artifact Revision 记录版本，确认前重新校验；
- 已确认后的撤销走现有 Revision / Proposal，不覆盖历史证据；
- 候选不能直接修改 `identity.md`。

## 6. 验收

模块层：

- Trigger Key / Semantic Key 跨重启幂等；
- 助手输出、重复 Capture、转发引用、镜像不算独立证据；
- `no_change` 不产生任何写入；
- 失败回滚后无残留候选/生效；
- Scope 过滤：A 的私域成长不出现在 B 或群投影中；
- 候选不得修改人格文件。

隔离 Host + 探针：

- 成长投影只在预算内出现，且只含已确认内容；
- 阶段推进前后投影变化可解释；
- 未确认候选不出现；
- 卸载重载无重复触发。

真实 Host/Provider：

- 行为层只证明“变化可见”，不替代输入层证明。

## 7. 待拍板

- 反思触发预算的具体数值；
- Trigger/Candidate 键的持久化落点（新表或复用现有表）；
- 低影响候选是否允许规则确认；
- 全局抽象的最少独立来源数。
