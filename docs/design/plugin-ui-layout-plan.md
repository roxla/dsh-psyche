## 1. 设计目标

沿用宿主全局侧栏；插件在中央面板内统一采用页头、横向页签与正文，页内最多一层分类。用户进入后能回答三个问题：现在是否正常、数据在哪里、应该在哪里修改设置。

科技感来自干净的深色层次、准确的对齐、少量青蓝强调与清楚的运行状态。保留宿主浅色主题适配。卡片、表格、表单和日志使用同一组颜色与尺寸，不再在不同页分别定义整套样式。

基本原则：

1. 概览只放摘要与需要处理的事项，详情进入所属页面。
2. 数据与相应配置可互相跳转；每项设置只有一个有效编辑入口。
3. 可编辑、只读、强制规则、生效时机均有明确文字，不能只靠颜色或禁用开关表达。
4. 当前值、实际运行状态、尚未保存的值分别展示；保存成功不等于已在当前运行代生效。
5. 未接入的数据使用说明明确的空态；不展示演示图、假分数或用 0 代替读取失败。

## 2. 页面框架

桌面布局：插件页面渲染在宿主 `main` 槽位内，宿主已提供左侧全局侧栏与窗口外框；插件只负责页面页头、页内导航与内容，不再绘制第二套宿主窗口。

**UI-1 导航冻结：各宽度统一使用页头下方的横向页签**，沿用现有「页头 + 横向页签 + 独立滚动画布」外壳；宽屏左侧二级侧栏从本轮移出，作为后续独立提案，不在 UI-1 出现，也不引入「记住侧栏展开状态」的新偏好。页签是二级导航，不是宿主侧栏的替代；页签溢出时单行横向滚动，不换行成多行。

导航形态按**内容容器宽度**分档（用 `main` 内容区宽度，不用 viewport；宿主侧栏可折叠）：

| 内容宽度 | 导航形态 |
| --- | --- |
| 所有宽度 | 同一组横向页签（单行，超出横向滚动），页头下方；内容宽度 <900px 时内容单列，不切换成下拉选择器 |

```text
概览（页面标题）                               当前状态 / 刷新
──────────────────────────────────────────────────────────────────
[概览] [记忆] [情绪与关系] [QQ 通道] [用量与花费] [设置] [运维与诊断]
──────────────────────────────────────────────────────────────────
关键摘要 / 需要处理的问题
主要内容：表单、列表、图表
补充说明 / 高级选项
```

页头由插件绘制（宿主 `main` 槽位不提供页面标题），但只写当前页面标题与状态；「心灵」品牌已在宿主侧栏出现，不在页头重复绘制品牌块、窗口边框或演示角标。页面只有一个主标题。右上角放与当前页面有关的动作，主要动作最多一个。列表详情采用同页展开或已有宿主详情能力；第一版不为布局改造增加复杂弹窗体系。

### 4.1 生效与保存

- `立即生效`：仅用于已接入可写偏好的项。提交中锁定该项，成功后显示已保存，失败保留原值并在该项旁说明。
- `重启生效`：宿主启动期配置。插件内显示摘要和「前往宿主设置」；宿主负责保存配置。没有可信的待应用状态时，不声称存在某次未生效更改。
- `只读`：使用文字值或状态标签，不画一个看起来可以点击的开关。
- `始终开启`：最终完整性检查以规则说明展示，不提供关闭控件。
- `跟随配置`：`promptSection` 必须保留三态，使用「跟随配置 / 开启 / 关闭」选择器。不能用二态开关丢掉继承语义。

#### 4.1.1 偏好保存行为（UI-1 功能交付）

当前 `src/client/index.ts:5601` 的 `savePref()` 是统一 `saving` 状态、失败只 `console.warn`。UI-1 必须把它升级为逐项可验证的行为，继续复用现有 `POST /api/psyche/prefs`，不新增写接口：

1. **三态**：`sea` 为布尔；`promptSection` 必须提交 `true`/`false`/`null` 三种值，`null` 表示「跟随配置」，不能用布尔开关丢掉继承。
2. **服务端确认后才更新**：本地只做「提交中」标记；成功后用服务端返回/下一次 panel 快照确认，再解除锁定并显示「已保存」。
3. **失败保留原值**：请求失败或非 2xx 时，控件回到提交前的值，在对应行显示可读错误（含 HTTP 状态或稳定错误码），不能只写控制台；`saving` 必须复位。
4. **旧响应不覆盖新操作**：为每次写入分配递增序号或使用 `AbortController`；快速连续拨动、切换页签或面板轮询返回时，较早的响应不得覆盖较新的本地意图。
5. **局部锁定**：只锁定正在提交的那一项；其他开关仍可操作，不整页禁用。
6. **不伪装宿主配置**：宿主配置项不调用该接口；保存失败与「重启生效」不得混为同一种提示。
7. **数据未就绪**：面板数据未到达或读取失败时，控件显示加载/失败态并禁用，不能把默认值当作已确认；提供局部重试，不整页刷新。
8. **成功来源与文案**：以 `POST /api/psyche/prefs` 返回的 `prefs` 为准更新控件；随后的 panel 轮询若与更新的本地提交序号冲突，以较新提交为准。`src/client/index.ts:235` 现有「null 表示不可热改」的旧注释与 `prefs.ts` 语义相反，UI-1 一并改正，界面文案固定为「跟随配置」。

对应验收：三态提交值、成功确认、失败回滚与行内错误、快速双击/连续切换、切页后返回状态、轮询覆盖防护、面板读取失败时的控件禁用与重试。

本阶段不新增通用「保存全部」按钮：可改偏好与宿主配置有不同写入位置，不伪装成同一笔事务。若以后确需插件内编辑配置，须先单独设计宿主写入授权、校验、持久化和重载能力。

### 4.2 群白名单布局

群聊分类是 UI-3 的前置项：字段契约未批准前不新增「群聊」页签、不展示空列或示例值；届时群列表放在 QQ 通道的「群聊」分类，设置页只放相同数据的简短摘要和管理入口。UI-1/UI-2 的 QQ 页只有「连接与私聊 / 诊断事件 / 运行日志」三类。

列表列为：群标识（脱敏）、采集模式、回复状态、时区、静默时段。单行展开才显示名称触发、合并窗口、小时上限、输入校验状态及未回复原因。

- 「已在白名单」「允许采集」「回复已开启」「具备运行能力」分别展示，不合并为一个绿色“已启用”。
- 生产输入证明未接入时，明确显示「模型输入校验尚未就绪，群回复保持关闭」。
- 用户管理群白名单仍进入宿主插件设置；本规划不新增群发送、审批、账号登录或进程控制入口。
- 当前 `/api/psyche/qq` 没有群策略/调度摘要；该列表是待补充的只读展示提案，不能直接假定接口已有这些字段。
- 群昵称只有存在可信配置/平台来源时才使用；未知时显示脱敏群标识，不能推断联系人身份。

### 4.3 宿主配置不在插件内镜像

DSH 的插件配置由宿主 Plugins 页面渲染（`plugins.bundle.config` / `plugins.row.config`），布局、保存与「重启生效」语义归 Host。心灵的「设置」页因此只做两件事：

1. 编辑**插件自有偏好**（当前只有 `sea` 与 `promptSection`，后者必须保留三态）。
2. 展示宿主配置的**只读摘要与入口**（「打开宿主插件设置」），不渲染同名字段、不提供第二个保存按钮、不假设宿主表单可以按本提案分类重排。

`立即生效` 标签只能授予已确认存在服务端热路径的偏好；`重启生效` 与 `只读` 以宿主启动期来源为准。`src/lib/panel.ts` 里描述符的 `apply` 字段只作线索，上线前逐项对照真实运行时来源；无法确认的字段一律按只读或省略处理，不能凭描述符宣称可热改。

本阶段不新增通用「保存全部」按钮：可改偏好与宿主配置有不同写入位置，不伪装成同一笔事务。若以后确需插件内编辑宿主配置，须先单独设计宿主写入授权、校验、持久化和重载能力。

## 5. 统一视觉规范

**宿主 Theme token 是唯一主题来源。** 已确认宿主暴露 `--dsw-alias-*`（bg-base / bg-layer-1 / bg-layer-2 / bg-overlay、border-l1/l2、label-primary/secondary、state-success/warn/error/idle、brand-primary）与 `--dsw-specific-sidebar-fill`；深浅主题由宿主切换。插件不得写死深色 `#0B1120` 一类色值，也不得用 `light-dark()` 或 `prefers-color-scheme` 猜测主题——宿主可能用 class/属性切换，系统偏好不等于宿主主题。

局部语义变量统一以宿主 token 派生：

| 插件变量 | 派生来源 | 用途 |
| --- | --- | --- |
| `--lb-bg` | `--dsw-alias-bg-base` | 页面底色（可透明，交给宿主） |
| `--lb-panel` | `--dsw-alias-bg-layer-1` | 面板/卡片 |
| `--lb-panel-2` | `--dsw-alias-bg-layer-2` | 嵌套块、表头 |
| `--lb-nav` | `--dsw-alias-bg-layer-2` 或 `--dsw-specific-sidebar-fill` | 页签/选中底 |
| `--lb-text` | `--dsw-alias-label-primary` | 正文 |
| `--lb-muted` | `--dsw-alias-label-secondary` | 次要文字 |
| `--lb-line` | `--dsw-alias-border-l1` | 细分隔线 |
| `--lb-line-strong` | `--dsw-alias-border-l2` | 强调边框/焦点外层 |
| `--lb-accent` | `--dsw-alias-brand-primary` | 当前导航、主操作、主要图形；不另造青蓝近似色 |
| `--lb-accent-soft` | `color-mix(in srgb, var(--lb-accent) 14%, var(--lb-panel))` | 选中背景、主按钮底、图表强调面积 |
| `--lb-accent-ink` | `--dsw-alias-label-primary` | 主按钮文字；不在强调底上硬写白/黑 |
| `--lb-ok/warn/error` | `--dsw-alias-state-success/warn/error-primary` | 状态语义色 |
| `--lb-ok/warn/error-bg` | `color-mix(in srgb, var(--lb-ok/warn/error) 12%, var(--lb-panel))` | 状态横幅/轻提示背景 |

实现时先 `var(--dsw-alias-*, 兜底值)` 读取，兜底值只用于旧宿主或独立预览；不得让兜底值在宿主内覆盖真实 token。`color-mix` 只做同一主题内的透明混合，不引入第二套色值。未列入 Theme 的 token（例如现有代码用到的 `--dsw-alias-label-tertiary`、`--dsw-alias-interactive-bg-hover`）只能带 fallback 使用，不能作为设计前提。

图表也必须使用同一套变量：现有客户端在 `src/client/index.ts:2553` 附近写死了深色文字/背景，迁移时改为从 `--lb-text`、`--lb-muted`、`--lb-line`、`--lb-accent` 派生，并随宿主主题切换重绘；不得只在卡片外壳换 token 而图表仍固定深色。

主题切换检测：CSS 变量由宿主属性自动生效；需要听变化的只有图表。实施时监听宿主主题属性（`documentElement` 上的 `data-ds-theme*` 或等价 class/属性）并在变化后按新 token 重建/重绘概览与用量图表，同时清理旧实例与监听器；不得用 `matchMedia('(prefers-color-scheme)')` 推断宿主主题，也不得只在页面挂载时读一次计算样式。

科技感只出现在信息层级和细节：少量强调色、清楚的网格和精细的状态。现有全页渐变、卡片内叠卡片、发光描边、英文装饰副标题、低对比小字合并或移除。

## 6. 各类数据的展示纪律

- 所有计数标明范围与时间。QQ 计数是本进程启动以来，重启归零；不能标成历史累计。
- QQ 接收、交付 Host、未授权事件、拒绝回复、静默丢弃、发送错误分别显示，不能拿拒绝事件数当发送数。
- 用量只统计心灵自身任务；未配置价格时费用显示「未定价」，不是 0 元。
- 关系默认只展示档位，Trust 未评估单独显示；不增加亲密度分数、虚构雷达或关系网络。
- 情绪历史使用真实快照；无数据不画占位走势。33 维是可展开明细，不压在首页。
- Source、Event、Artifact 是不同对象；不将三者相加并称作“已记住的条数”，也不把比例当质量分。
- 群连续处理水位使用「已确认处理位置」等准确措辞；策略省略不是模型阅读，发送成功不是全部处理证明。
- 数据失败显示读取失败及最近成功快照时间，不能保留绿色“实时正常”；不存在快照时使用空态。
- Token、完整账号、内部 ID、原始证据正文不在首页、普通日志和列表中自动展开；普通页面不提供敏感信息复制按钮。

## 7. 响应式与可访问性

- 各宽度统一使用页头下方的横向页签（UI-1 冻结）；宽屏左侧二级侧栏不在本轮实现，作为后续独立提案评审。
- 内容 ≥900px：页签单行，概览可三列摘要，详细内容以两列或全宽列表为主，长表单保持单列阅读顺序。
- 内容 <900px：同一组页签单行横向滚动；内容单列，设置名、说明和值纵向排列，动作移至标题下。不切换成下拉选择器。
- 以 `main` 内容容器宽度决定断点，兼容宿主侧栏折叠/分栏，不只根据屏幕 viewport 推断可用宽度。
- 仅表格在确有必要时局部横向滚动；页面整体无横向滚动。避免多层固定高度与嵌套滚动。
- 控件有可读名称，原生键盘操作与可见焦点；不依赖 hover 展示必要操作。
- 加载、空态、未启用、读取失败、受限等状态有统一版式；只刷新局部内容，避免轮询导致整页跳动。
